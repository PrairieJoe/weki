# Weki v1.2.1 사용자 온보딩 투어 구현계획

> 실행 방식: 승인된 설계를 기준으로 subagent-driven development와 TDD를 적용한다.

## 목표

v1.2.1에 신규 사용자가 Weki의 핵심 흐름을 빠르게 이해할 수 있는 선택형 5단계 코치 마크 투어를 추가한다. 투어는 검색, 문서 등록, 결과·근거, 설정의 처리 모드, MYBOX를 설명하며 실제 문서 등록·검색·MYBOX 동작은 수행하지 않는다.

## 확정 정책

- 첫 실행 데이터 로드와 첫 렌더가 끝난 뒤 한 번만 자동 시작한다.
- 진행 완료 여부는 `localStorage`의 `weki.onboarding.v1.completed=completed`로만 관리한다.
- 기존 `사용 가이드` 버튼은 언제든 1단계부터 다시 시작하는 재생 진입점이다.
- 건너뛰기, 닫기, 완료 후에는 투어 시작 당시 화면으로 돌아간다.
- 단계 전환 시 대상 화면으로 자동 이동한다. 대상 요소가 없으면 중앙 카드로 대체한다.
- 네이티브 구현이며 외부 투어 라이브러리를 추가하지 않는다.
- 접근성은 `role=dialog`, `aria-modal`, 내부 포커스, 키보드 이동, Esc 종료, 종료 후 원래 포커스 복귀를 보장한다.

## 실행 순서

### Task 1: 온보딩 계약 테스트와 RED 기준

`test/onboarding.test.mjs`에 저장소 상태, 5단계 순서, 완료 저장, 재생 초기화, 종료 시 시작 화면 복귀를 검증하는 순수 테스트를 추가한다. `test/ui-contract.test.mjs`에는 렌더러의 재생 진입점과 5개 대상 훅, 대화상자 접근성 계약을 추가한다. 구현 파일은 이 태스크에서 만들지 않으며, 새 테스트가 예상대로 실패하는 실행 결과를 보고한다.

### Task 2: 온보딩 컨트롤러와 렌더러 연결

`src/onboarding.js`에 DOM 비의존 단계·상태 계약과 네이티브 코치 마크 컨트롤러를 구현한다. `src/main.js`에는 첫 렌더 뒤 자동 시작, `사용 가이드` 재생, 단계별 화면 자동 전환, 대상 훅, 시작 화면 복귀를 연결한다. 서버, DB, MYBOX API는 수정하지 않는다.

### Task 3: 시각 스타일과 Electron E2E

루트 `styles.css`에 코치 마크 오버레이·카드·진행 표시·반응형 스타일을 추가한다. fixture에 의존하지 않는 Electron E2E로 자동 시작, 5단계 전환, 완료 후 재진입, Esc 종료와 localStorage 완료 상태를 검증한다. 기존 fixture 기반 E2E의 누락 fixture 실패는 별도 상태로 유지한다.

### Task 4: 사용자 문서와 릴리즈 자료

README, `docs/RELEASE_NOTES_V1.2.1.md`, `docs/USER_TEST_CHECKLIST.md`, PRD 또는 관련 사용자 문서에 온보딩 투어의 시작·재생·건너뛰기·종료 동작과 접근성 기대치를 반영한다. v1.3.0 전체 문서 재처리 범위와 섞지 않는다.

### Task 5: 종합 검증과 커밋 병목 처리

단위·계약 테스트, 빌드, fixture-free E2E, 기존 E2E를 실행하고 결과를 분류한다. 변경 diff와 릴리즈 아티팩트 계약을 점검한 뒤, 현재 호스트 사용량 제한으로 막혔던 Git add/commit을 동일 작업트리에서 재시도한다. 제한이 계속되면 우회하지 않고 정확한 차단 원인과 커밋되지 않은 파일을 보고한다.

## 검증 기준

- 자동 시작/완료 저장/재생/건너뛰기/원래 화면 복귀가 테스트된다.
- 5단계의 화면 전환과 대상 훅이 UI 계약 테스트에 고정된다.
- 포커스와 Esc 종료가 E2E 또는 단위 테스트로 확인된다.
- 기존 v1.2.1 변경과 문서 정책이 회귀하지 않는다.
- 누락된 기존 PDF/HWPX fixture 때문에 실패하는 테스트는 제품 결함과 분리해 보고한다.
