# Weki 이용자 테스트 체크리스트

이 문서는 최근 이용자 테스트에서 제기된 설정·runtime·MYBOX 관련 질문을 실제 사용자 흐름으로 재확인하기 위한 체크리스트입니다. 다운로드 행위 자체를 문제로 삼지 않습니다. 클라우드 또는 MYBOX를 통한 설치가 필요한 경우에도, 테스트의 초점은 **어떤 구성요소가 보이는지, 설치 가능한지, 설치 후 어떤 상태와 처리 모드가 되는지**입니다.

## 테스트 목적

- 최초 설치 상태에서 고품질 검색 구성요소의 의존관계가 사용자에게 오해 없이 전달되는지 확인합니다.
- semantic model, semantic reranker, document renderer의 설치·업데이트·재시작 상태를 확인합니다.
- 세 구성요소 설치 이후 기본 처리 모드가 의도대로 Local AI로 전환되는지 확인합니다.
- MYBOX 백업·카탈로그 동기화와 원본 지연 복원 흐름이 비전공자에게 이해되는지 확인합니다.
- MYBOX 접근·배포본 문제와 문서 원본 다운로드 문제를 서로 다른 이슈로 구분합니다.

## 준비 조건

가능하면 다음 환경을 각각 준비합니다.

1. 구성요소를 하나도 설치하지 않은 신규 설치 환경
2. semantic model만 설치·적용된 환경
3. 세 구성요소가 모두 설치·적용된 환경
4. 새 버전 manifest가 있는 업데이트 환경
5. 공개 배포본은 없고 MYBOX 배포본만 있는 환경
6. MYBOX 토큰이 없거나 검증에 실패한 환경
7. 기존 문서가 이미 등록된 환경과 문서가 하나도 없는 환경

테스트 중에는 화면 캡처, 앱 버전, 구성요소 버전, 상태 문구, 수행한 클릭 순서를 함께 기록합니다. 토큰과 문서 원문은 캡처·공유하지 않습니다.

## 필수 시나리오

| ID | 사용자 행동 | 기대 결과 | 기록할 내용 |
|---|---|---|---|
| RUNTIME-01 | 신규 설치 후 설정 화면을 엽니다. | semantic model·semantic reranker·document renderer 3개 행이 모두 보입니다. 없는 항목도 사라지지 않고 `배포 준비 중` 또는 `설치 필요`로 구분됩니다. | 각 행의 이름, 상태, 버전, 설치 버튼 유무 |
| RUNTIME-02 | semantic model이 없는 상태에서 Local AI 처리 모드를 확인합니다. | Local AI 선택은 모델 설치 전에는 사용할 수 없고, 경량 처리는 계속 선택·실행할 수 있습니다. | 비활성화 이유가 이해되는지, 경량 처리 가능 여부 |
| RUNTIME-03 | semantic reranker 행을 확인합니다. | `semantic-reranker`가 화면에서 누락되지 않고 bundled 1.0.0(982 bytes, SHA-256 `31db99da8c2d7c8a1df461ffe652fe2e29d14505a455edbbe6cd5364686e842e`) 설치 대상으로 표시됩니다. manifest의 실제 hash·크기 검증을 포함한 설치 오류가 발생하면 오류 원인과 `재시도`가 보입니다. | bundled 출처·버전·hash, 설치 오류의 실제 원인, 재시도 가능 여부 |
| RUNTIME-04 | 설치 가능한 구성요소에서 `전체 설치`를 누릅니다. | semantic model → semantic reranker → document renderer 순서로 진행률이 보입니다. `document-renderer`가 MYBOX 전용이고 `MYBOX 배포본 없음`이면 실패가 아닌 보류 상태로 표시되며, 설치 가능한 구성요소는 계속 완료됩니다. 실제 실패 시 원인과 `재시도`가 보입니다. | 실제 설치 순서, 진행률, MYBOX 배포본 없음의 비실패 처리, 실패·재시도 안내 |
| RUNTIME-05 | 세 구성요소 설치를 완료한 뒤 버튼과 버전을 확인합니다. | 동일 버전이면 반복 설치 버튼이 활성화되지 않습니다. 더 높은 버전이 있을 때만 `업데이트 가능`으로 표시됩니다. 실제 실패가 없으면 renderer가 unavailable이어도 성공한 구성요소를 적용하기 위한 앱 재시작이 가능하고, 실제 실패가 있으면 자동 재시작하지 않으며 `재시도`가 제공됩니다. | 동일 버전 재설치 방지, 업데이트 표시, renderer unavailable과 실제 실패의 구분, 재시작 안내 |
| MODE-01 | 신규 설치 직후 기본 처리 모드를 확인하고 문서를 등록합니다. | 설정값은 `설치 상태에 따라 자동`으로 보이고, 구성요소가 준비되기 전 실제 처리는 경량 처리로 진행됩니다. | 설정값과 작업 카드의 실제 적용 모드 |
| MODE-02 | 세 구성요소를 모두 설치·적용한 뒤 새 문서를 등록합니다. | 자동 기본값이 새 문서부터 Local AI를 사용합니다. 기존 문서는 자동으로 재처리되지 않습니다. | 새 문서의 적용 모드, 기존 문서의 처리 상태 |
| MODE-03 | 기본값을 `경량 처리`로 직접 지정하고 문서를 등록합니다. | 사용자가 명시한 경량 처리가 유지되고 Local AI로 자동 승격되지 않습니다. | 선택값 보존 여부 |
| INDEX-01 | 설정 화면에서 검색 색인 관리 기능을 찾고, 안내 문구를 확인합니다. | 사용자용 검색 색인 관리 UI는 보이지 않습니다. 내부 검색 색인 재생성 API는 마이그레이션·복구용으로만 유지되며, 전체 문서 재처리(파싱·OCR·AI·Embedding·색인 재실행)는 v1.3.0 검토 항목임을 안내합니다. | 사용자 UI 부재, 내부 복구 API와 전체 문서 재처리의 구분 이해 여부 |
| BACKUP-01 | 설정 화면에서 MYBOX 백업 영역을 찾습니다. | MYBOX가 유일한 지원 백업 경로로 표시되며, v1.2.0의 로컬 `.weki` 파일은 생성·복원 대상이 아니고 자동 삭제하지 않는다는 안내가 보입니다. | 기능을 찾는 데 걸린 시간, `.weki` 비호환 안내 이해 여부 |
| BACKUP-02 | MYBOX 업로드와 검색 DB 동기화를 실행한 뒤, 원본이 없는 검색결과에서 원본을 엽니다. | `knowledge-base.json` 카탈로그와 원본이 MYBOX에 업로드·동기화되고, 원본 열기 시 필요한 파일만 Hash 검증 후 지연 복원됩니다. | 업로드·동기화 결과, 원본 지연 복원 여부, Hash 검증 오류 유무 |
| STATUS-01 | 검색 엔진과 runtime 상태를 확인합니다. | 화면에 `healthy`·`degraded` 같은 내부 영어값 대신 `정상 작동`·`일부 기능 제한`·`사용할 수 없음` 등 쉬운 한국어가 표시됩니다. | 이해되지 않는 표현과 원래 의미 |
| MYBOX-01 | 공개 배포본이 없고 MYBOX에만 runtime 배포본이 있는 환경에서 설정을 확인합니다. | 구성요소 행에 `MYBOX 배포본` 여부가 표시되고, MYBOX 접근·인증이 정상일 때 설치 대상이 됩니다. | 접근 경로, 출처 표시, 설치 가능 여부 |
| MYBOX-02 | MYBOX 토큰이 없거나 검증에 실패한 상태에서 로컬 기능을 사용합니다. | MYBOX 동기화·MYBOX runtime 설치만 제한되고, 로컬 검색·경량 처리는 계속 사용할 수 있습니다. | 제한 범위, 안내 문구 |
| MYBOX-03 | MYBOX runtime 설치와 원본 열기를 각각 수행합니다. | runtime 설치를 위한 배포본 접근과 검색 결과에서 원본을 지연 다운로드하는 동작이 별도 흐름으로 이해됩니다. 어느 쪽도 다운로드 행위 자체를 오류로 표시하지 않습니다. | 두 흐름을 사용자가 구분하는지 |

## 이용자에게 직접 물어볼 질문

테스트 진행자는 다음 질문을 그대로 사용해도 됩니다.

- 세 구성요소 중 지금 설치할 수 있는 것과 아직 배포 준비 중인 것을 구분할 수 있나요?
- `전체 설치`를 누르면 어떤 일이 어떤 순서로 진행될 것 같나요?
- 세 구성요소가 모두 준비된 뒤 기본 처리 모드가 바뀐다는 설명이 충분한가요?
- 기존 문서도 자동으로 다시 처리될 것이라고 오해하지 않았나요?
- MYBOX 백업, 검색 DB 동기화, 원본 지연 복원이 각각 어떻게 이어지는지 설명할 수 있나요?
- v1.2.0의 로컬 `.weki` 파일을 v1.2.1에서 복원할 수 없고 자동 삭제하지 않는다는 안내가 명확한가요?
- 사용자 설정 화면의 검색 색인 관리 UI는 제거됐지만, 내부 검색 색인 재생성 API는 마이그레이션·복구용으로 유지된다는 점이 명확한가요?
- 내부 검색 색인 재생성 API와 전체 문서 재처리의 차이, 그리고 전체 문서 재처리가 v1.3.0 검토 항목이라는 점이 명확한가요?
- `MYBOX 배포본`과 `MYBOX에서 원본 가져와 열기`가 서로 다른 기능이라는 점이 명확한가요?
- `정상 작동`, `일부 기능 제한`, `배포 준비 중` 중 이해하기 어려운 표현이 있나요?

## 판정 기준

- 필수 시나리오에서 P0/P1 수준의 데이터 손실·잘못된 외부 전송·복구 불가 문제가 없어야 합니다.
- 신규 설치 사용자가 3개 구성요소의 상태와 설치 가능 여부를 별도 설명 없이 구분할 수 있어야 합니다.
- 사용자가 구성요소가 없을 때도 경량 처리와 로컬 검색을 계속 사용할 수 있어야 합니다.
- 세 구성요소 적용 후 새 문서의 기본 모드가 Local AI가 되는 흐름과 기존 문서가 자동 재처리되지 않는다는 정책을 이해할 수 있어야 합니다.
- MYBOX 인증 실패가 로컬 기능 전체 중단으로 오해되지 않아야 합니다.
- 사용자가 로컬 `.weki` 파일을 현재 복원 경로로 오해하지 않아야 하며, MYBOX 카탈로그 동기화와 원본 지연 복원 흐름을 구분할 수 있어야 합니다.
- 전체 문서 재처리가 현재 릴리스에서 실행되는 기능으로 안내되지 않아야 합니다.
- 내부 검색 색인 재생성 API가 사용자 설정 기능이나 전체 문서 재처리로 오해되지 않아야 합니다.
- `healthy` 같은 내부 상태값이 이용자 화면에 그대로 노출되지 않아야 합니다.
